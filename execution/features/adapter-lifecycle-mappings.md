# Adapter Lifecycle Mappings Execution

Feature ID: adapter-lifecycle-mappings
Status: validated
Why: Adapter lifecycle definitions must be available locally before future sync work can safely map SpecSpine status to upstream artifacts and agent focus.

## Milestones

- Define native lifecycle meaning and upstream phase mappings for each adapter.
- Expose mappings through a new `specspine adapters lifecycle` command.
- Preserve local fusion state reporting without probing external tools.
- Document the command and update dogfood artifacts.
- Verify behavior with focused tests and repository validation.

## Tasks

- [x] Add stable adapter lifecycle mapping records for OpenSpec, Spec Kit, and Superpowers.
- [x] Cover `proposed`, `planned`, `in-progress`, `implemented`, `validated`, and `archived` for every adapter.
- [x] Include mapping ids, native meanings, upstream phases, upstream artifacts, agent focus, and local commands.
- [x] Read `.specspine/fusion.yaml` only to determine local enabled state and adapter config paths.
- [x] Report adapter config existence without reading upstream configs or invoking probes.
- [x] Add JSON and text renderers for lifecycle reports.

- [x] Add unit tests for JSON shape, fused workspaces, plain workspaces, missing configs, text output, and external-tool isolation.
- [x] Update README, architecture docs, upstream policy, product spec, execution plan, review notes, and agent guidance.

## Dependencies

- Existing adapter metadata in `specspine.adapters`.
- Existing fusion config generated by `specspine fuse`.
- Existing native lifecycle statuses and feature readiness contracts.

## Open Questions

- Whether future remote sync should enrich these mappings with remote issue state, project fields, or pull request state.
- Whether adapter lifecycle mappings should later include per-status required evidence beyond the current local commands and agent focus.

## Agent Handoff

- Run `specspine adapters lifecycle . --json` before implementing future adapter sync work.
- Run `specspine status . --json --validate --feature-summaries` when comparing local feature lifecycle states.
- Run `specspine feature handoff adapter-lifecycle-mappings . --json`.
- Run `specspine feature tests adapter-lifecycle-mappings . --json`.
- Run `specspine feature ready adapter-lifecycle-mappings . --json`.
- Run `specspine validate . --fusion --features`.
